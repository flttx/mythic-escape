# Mythic Escape · 五章视觉品质生产线（设计版 v0.5）

> 状态：**PIPELINE_DESIGNED / NOT_YET_VALIDATED**。本文件描述未来要经首章实战验证并提炼成 Skill/自动化工作流的规范，不代表已有这些可调用的新 Skill。宏观交付 M1→M2→M3；局部 A/C 镜头、短版 PrototypeSlice 只作为 M1 内部迭代/测试步骤，绝不形成不断新增的 V4/V5 交付链。
> 范围：PC UE5.8.3、电影级写实、真实可玩、近景高精资产；章节保留各自巨兽身体结构、地形、光色与灾难机制。执行入口遵守 `AGENTS.md`，质量门遵守 `VISUAL_QA.md`。

## 1. 两条并行线与贯穿全章的验收

| 开发线 | 实际工作 | 每章交付证据 |
|---|---|---|
| **内容线（Content）** | 完整空间与路网、角色/载具、章节事件、危险预警→作用→恢复、倒计时、失败/重试、结局 | UE 原生地图/资产可加载；真实 PIE 全章可通关、可失败、可重试；阶段计时/安全区和输入验证 |
| **视觉品质线（Visual Quality）** | 高精度 Hero Asset、骨骼蒙皮/动画、PBR 材质/地形/海洋、灯光与天气、巨物尺度构图、交互 VFX/音效、LOD/性能、摄影机 QA | 可核实玩家 GameViewport 的 A–E 镜头与动作片段、模型/材质/骨骼来源、触发同步证据、硬件/CPU/GPU/显存记录 |

**两条线同步，均为关卡完成条件**。内容线通过但画面粗糙仅 `PLAYABLE_ONLY`；画面漂亮却不可玩仅 `VISUAL_ONLY`；不能称关卡完成。正式质量遵照 `VISUAL_QA.md`，不得用编辑器视口、离线 MRQ 或概念图冒充游戏实拍。若真实 GameViewport 取证暂受阻，以 `NOT_VERIFIED` 记录并继续独立工作，不假设通过。

## 2. 单章视觉制作的可复用步骤

1. **尺度/镜头基准**：确认玩家眼高与相机 FOV、巨兽真实比例、船/潜艇/长船/树木/悬崖等参照，选出 A 登场与 C 近景 Hero 镜头。每章都需要实拍；不能统一照搬克拉肯的深海色调。
2. **资产需求与来源审计**：依据镜头距离决定 Hero/中景/远景网格层级和可动结构，选择 Tripo、合法 Fab/现有模型或 Blender 自制。记录来源、许可和商用范围；不把超高面数当质量指标。
3. **Blender 资产处理**：核对几何轮廓、拓扑、尺寸与轴心；必要时重拓扑/细节烘焙；保留高精源，制作适合 UE 的网格、PBR、LOD 与近景形变所需结构。
4. **骨骼/动作**：选择适配的 Tripo 自动骨架或 Blender 定制骨骼；用 UE Control Rig/AnimBP/IK/Sequencer 组合实际运行控制。动作接触事件与攻击碰撞、船体受力、地震/风场、VFX 和音频同步。
5. **环境渲染**：针对该章地形/天气选 Water、PCG、Niagara、Lumen、贴图与灯光策略；建立可重现的相机、光照与压力测试场景，视觉品质与实际玩法同场验证。
6. **真实运行双验收**：测试 A/C 后扩展 B/D/E，记录真实玩家画面、运动、受力时序、近景细节/动画变形、帧耗时、显存和失败原因；未达到目标则逐项改进，不能只提高渲染预设。
7. **交付/知识沉淀**：保存已通过的 UE 原生资产、Blender 源文件、最小化脚本/参数/验收图、可重复操作步骤、问题与回退方案。无证据的“经验”只能列为假设。

以上步骤应以**小批量、可重复且可回退**的方式执行；不给每章复制巨型基类、完整的另一章场景、全套引擎插件或完全相同的生物骨架。摄像机/QA/资产导入可共用，巨兽结构与关卡差异必须保持专属。

## 3. 首章之后怎样提炼成真正可复用的 Skill

**触发条件**：Kraken FullChapter（14–18 分钟设计目标）具备真实完整通关与主要失败重试测试；高精 Hero Assets/骨骼/PBR/动画交互和 A–E 玩家视角的实际游戏证据完成；目标硬件的性能问题已记录、已解决或被明确接受。只完成 5–7 分钟内部 `PrototypeSlice`、一张好看的截图或一个自动绑定任务**不满足正式提炼门槛**。

**先复盘再抽象**：
- 把首章可重复操作拆为小能力，优先扩展现有 `mythic-visual-qa`（真实玩家 GameViewport 取证、镜头质量与帧耗时）和 `blender-cli` 工作流（导入/轴心/拓扑/骨骼/导出校验）。除非已有 Skill 不适合承载，再考虑新建项目级 `mythic-asset-pipeline`、`mythic-creature-animation` 或 `mythic-cinematic-lighting`。不提前创建空壳 Skill。
- **每个候选 Skill 至少具备**：触发场景和不触发场景、输入与输出、工具/版本依赖、操作步骤、验收条件、失败回滚、脚本/示例、至少一次首章成功执行记录；避免把整章硬编码成“通用”脚本。
- 将可复用模块与章节专属数据剥离：单位/坐标、源网格检查、LOD/性能、骨骼动作事件、PBR 验证、真实游戏截图工具可以复用；巨兽解剖、攻击、环境流体/岩崩/气流、色彩和剧情不能简单复制。
- **复用试验**：用利维坦或另一种明显不同的模型/环境执行一轮“干净输入→自动/半自动处理→UE 实跑→视觉 QA”，发现通用步骤遗漏就修订。首章跑通仅证明第一例有效；二次试验通过后才标记 `REUSABLE_VALIDATED`。
- 输出 `SKILL.md`（若确需新建）、必要的脚本与测试数据、版本和前后示例；在 `PROGRESS.md` 写明创建/调用/验证事实。不得以本设计文档宣布某个未来 Skill 已安装或有效。

## 4. 三个有限的交付里程碑

- **M1 首章正式交付**：Kraken FullChapter 14–18 分钟目标；内容线全流程与视觉品质线 A–E/高精资产/骨骼/水面/性能并行；短版 `PrototypeSlice` 只用来快速验证关键链路，不成为长期独立阶段。首章通过之后整理首批 Skill 候选与复用样本。
- **M2 后四章并行制作和复用验证**：Leviathan、Jormungandr、Behemoth、Ziz 各完成完整玩法与各自 A–E 实时视觉门；优先复用 M1 中**已验证**的资产/QA/性能工具，首个不同场景复用成功后再确认 Skill 稳定。不要为了等某一海水效果完美而阻塞无依赖的山岳或天空制作。
- **M3 全五章收尾发布**：所有章节的通关、失败、重试、贴图/高精网格、动作碰撞同步、镜头画质、舒适度、性能、授权与打包验证；未通过的质量门不得默认为通过。不再自动增加 V4/V5 式的阶段。

## 5. 运行与资源底线

- Unreal 编辑器/MCP 只连接 Mythic Escape 的端口 8001，不碰 8000 其它项目。外部 Demo 见 `UE_REFERENCES.md`，先用引擎已安装插件/模板，必要时在隔离工程验证。
- `CaptureViewport` 目前只证明编辑器相机，不是可靠玩家视图。先解决真实运行时采集再称视觉 PASS，工具不可用时记录 `NOT_VERIFIED` 而不伪造图像/帧率。
- 低模仅用于不可见逻辑代理或距离允许的 LOD，不充当正式近景 Hero Asset；模型的几何、PBR、骨骼、光照都以镜头和性能实测调优。
- 后四章按 **“通用生产方法 + 章节独特风格”** 复用，而不是把第一章的海水、触手、风暴套到所有神话巨兽上。
